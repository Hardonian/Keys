# Security Policy

## Supported Versions

Security updates apply to the `main` branch. If you depend on tagged releases, upgrade to the latest release before reporting issues.

## Security Model

The Keys library operates with the following security principles:

- **Open source transparency.** All code is visible and auditable. No hidden processing logic.
- **Least privilege.** Infrastructure and access are configured to require minimum necessary permissions.
- **Human gates.** Administrative changes require human approval. No autonomous escalation.
- **Auditability.** Actions are logged and available for review by your organization.

## Artifact Security

Each artifact in the library includes:
- Documented assumptions and preconditions
- Known security considerations and limitations
- Recommended validation steps before use

Your organization remains responsible for:
- Reviewing artifacts for your specific context
- Validating outputs before production use
- Applying your security policies and controls

## Reporting a Vulnerability

Please report security issues privately through responsible disclosure.

1. Open a private GitHub Security Advisory on this repository.
2. Include reproduction steps, impact assessment, and any relevant logs or screenshots.
3. Do not open public issues for security vulnerabilities.

## Response Timeline

We acknowledge reports within 5 business days and provide a remediation plan or status update as soon as practical.
